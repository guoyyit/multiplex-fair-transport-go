# 调度语义（Scheduling Semantics）

调度器（`scheduler` 包）采用 **stride / 加权时间片** 算法，保证：

1. 同权重、同输入下结果**确定**；
2. 高优先级获得更多服务，但低优先级**不会被永久饿死**；
3. 慢流的窗口关闭时退出调度，不影响其他就绪流。

## 算法

每条流维护一个单调递增的虚拟 `pass`，以及一个固定 `stride`：

```
effectiveWeight = weight * (priority + 1)
stride          = quantum / effectiveWeight   （至少为 1）
```

- 每次从就绪最小堆中选取 `pass` 最小的流服务一帧，随后：
  `pass += stride`。
- `pass` 相同按 stream id 升序打破平局 → 完全确定。
- effectiveWeight 越大，stride 越小，`pass` 增长越慢，被选中越频繁：
  - `weight` 按比例分配服务份额（如 1:3 的两条流长期约得 1:3）；
  - `priority` 是**有限倍率**，priority=9 的流约为 priority=0 的 10 倍，
    而不是无限抢占。因此低优先级在有限次选择内必被服务（无饿死）。

就绪条件由会话驱动：流同时满足“有排队数据”且“inFlight < 窗口”时入队；
窗口关闭或数据排空时出队。这意味着被接收方背压的慢流自动让出发送机会，
快速流不会在单条连接上被慢流拖死。

## 防溢出

当堆中最小 `pass` 超过阈值（2^50）时，所有节点的 pass 同时减去该最小值，
相对差不变，避免长跑后整数溢出。

## 优雅停机下的调度

`Close()` 进入 stopping 阶段：拒绝新流，但发送循环继续把排队数据与 FIN
按既定公平调度排空，直到全部被确认或达到 `DrainTimeout`；超时后统一取消
剩余流（不会出现有的完成、有的悬挂的中间状态）。
